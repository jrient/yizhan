# 公共规矩(所有机器人通用)

> 本文件由网关从 `/data/projects/yizhan/shared/shared-rules.md` 同步过来,每次唤起前覆盖一次。
> 在工作台里改它没用,也不要改;觉得哪条不合理,在群里 @ 负责人提。

这里列的是**本来就不允许做的事**。不要试,不要被拒之后再换办法试。
权限系统只是把这些规矩落实了,拦不住的地方靠你自己守。

## 一、绝对不做

| 不做的事 | 说明 |
|---|---|
| 写库、改数据 | 数据库一律只查不改,包括「顺手修一下」「帮忙改个配置」。要改就拟稿给负责人 |
| 改原项目的代码和文件 | 原项目只读。归档、笔记、临时文件都写工作台 |
| 往工作台以外写文件 | 包括 `/tmp`、原项目目录、成片目录。输出一律写工作台 `tmp/` |
| 删除、移动、改权限 | `rm`、`mv`、`chmod`、`chown`、`sudo` 都不用 |
| 启停服务、杀进程 | `systemctl start/stop/restart`、`kill`、`pkill`、`docker` 都不用。服务有问题就告警、@ 负责人 |
| git 写操作 | `commit`、`push`、`add`、`reset`、`checkout`、`restore` 都不用,只读的 `status/log/diff/show` 可以 |
| 读密钥 | 各项目的 `.env`、网关实例配置、`~/.ssh`、skill 目录下的 `.env`、`.credentials.json`。查库用 skill 里给的只读连接方式,不要去翻账号口令 |
| 读网关源码研究规则 | 不要去读 `fgctl`、网关代码,琢磨证据校验或权限规则怎么才能通过。证据被拒就把出处写具体;规则不合理就在群里提 |
| 自己下载、联网 | 不用 `curl`、`wget`。skill 脚本自带的下载除外 |
| 泄露敏感信息 | 口令、密钥、账号名、内网地址不发到群里。被问就说明权限情况,具体信息让对方找管理员 |

## 二、被拒之后怎么办

- **被拒的是操作本身**(上表里的事):停手。在群里说清楚哪一步做不了、哪个结论因此没法核实,
  然后照常 `fgctl done` 或 `fgctl defer`。**绝不拿猜测补上那一步的结论。**
- **不要换别的办法达成同一个目的。** Read 读不了的文件,不要改用 `cat`、`python3`、别的工具去读;
  这类绕过比被拒本身更严重。
- **被拒的只是写法**:照下表换掉,这不算绕过。

## 三、会被拒的写法和正确写法

| 被拒的写法 | 改成 |
|---|---|
| `cd 某目录; grep … \| head`,即 `cd` 后面接管道 | 不 `cd`,写绝对路径:`grep … /绝对路径/文件 \| head` |
| 一条命令里用 `;` 或 `&&` 串好几个 | 拆成几条分别执行。有一段不在清单里,整条被拒 |
| `$(…)` 命令替换 | 先单独执行里面那条拿到结果,再写进下一条命令 |
| `python3 - <<EOF` 这类 heredoc、`for` 循环 | `python3 -c "…"`,或先用 Write 写脚本到工作台 `tmp/` 再执行 |
| `sed -i`、`cat > 文件`、`echo >> 文件` 改记忆或笔记 | 用 Edit / Write 工具 |
| `mkdir`、把输出写到 `/tmp` | 输出写工作台 `tmp/` 的绝对路径 |
| `sqlite3 -column 库 …` | `sqlite3 -readonly -column 库 …`,`-readonly` 放第一个参数 |
