# 机器人权限

机器人每处理一张卡都会唤起一次 `claude -p`。它能执行什么操作，由这里说的两样东西决定：
**权限模式**（实例配置里的 `permission_args`）和**允许清单**（工作台的 `.claude/settings.json`）。

## 当前状态

| 实例 | 权限模式 | 切换日期 |
|---|---|---|
| drama-auto | 受限：`--permission-mode dontAsk --permission-prompts none` | 2026-09-23 |

新实例用 `yizhan init` 生成时，默认是跳过权限模式（`--dangerously-skip-permissions`），方便第一天先跑通。
跑通后应当尽快切到受限模式，理由见下文「为什么要切」。

## 两种模式的区别

| | 跳过权限 | 受限 |
|---|---|---|
| 参数 | `--dangerously-skip-permissions` | `--permission-mode dontAsk --permission-prompts none` |
| 允许清单 | **整份不生效**，deny 也被绕过 | 生效：allow 里的放行，deny 里的拒绝，其余一律拒绝 |
| 遇到没预批的操作 | 直接执行 | **立即拒绝，不弹窗、不等人** |
| 适合 | 新实例第一天调通 | 正式运行 |

`--permission-prompts none` 的意思是「没有人来回答权限确认」，所以任何本该弹确认的操作都直接被拒。
这就是它不会卡在 shell 里等人的原因。

### 为什么要切

群消息是不可信输入，任何人都可以在群里要求机器人做任何事。跳过权限模式下，机器人实际做过这些事（都发生在 09-21）：

- 改了网关代码 `gateway/feishu.py` 和测试文件，然后自己重启了 listener
- 改了实例配置里的群白名单
- 15:04 把两条提示词从测试库同步写进了**线上库**

负责人随后定了规矩：**不许修改数据和项目代码，一次确认不等于授权**。但在跳过权限模式下，这条规矩只写在机器人的记忆里，没有任何机制强制执行。受限模式把其中能落实的部分落实了。

## 被拒之后会发生什么

要求：**没有权限就给提问的人反馈，不能卡在 shell 里等，也不能默默不回。**

```
claude 调用某个操作
   │
   ├─ 在 allow 里 ──→ 正常执行
   │
   └─ 不在 allow 里 / 在 deny 里 ──→ 立即返回「Permission … denied」
          │
          ├─ 机器人自己处理(派卡提示词与 skill 里写明的规矩)
          │    · 被拒的只是写法(heredoc、for 循环)→ 换成允许的写法,不算绕过
          │    · 被拒的是操作本身(写库、改文件、删除、联网、重启服务)→ 停手,
          │      在群里告诉提问人「哪一步做不了、哪个结论因此没法核实」,不拿猜测补上
          │
          └─ 本轮结束,dispatcher 读 result 里的 permission_denials 兜底
               · 每条被拒记入错误统计(控制台「统计」页的「权限拒绝」一类)
               · 私聊管理员(alert_open_id),附被拒的原命令
               · 机器人已自己收尾(卡是已答复/挂起)→ 不再多说
               · 卡没收尾 → dispatcher 在群里回一句「没有权限、已通知管理员」,
                 卡标成需人工处理(卡死),不再重派(重派只会再被拒一次)
```

标成需人工处理的卡，放开权限后到控制台「卡」页签点「重开」即可重新处理。

## 允许清单

位置：`~/.local/state/yizhan/<实例>/workspace/.claude/settings.json`
模板：`gateway/templates/workspace/.claude/settings.json`（`yizhan init` 时按实例渲染，`{project_dir}` 会替换成真实路径）

清单是按 09-21 到 09-23 机器人转录里**实际用过**的命令整理的。

**放行**

| 类别 | 内容 |
|---|---|
| 驿站自己的工具 | `fgctl` |
| 只读查看 | `ls` `cat` `head` `tail` `sed -n` `grep` `rg` `wc` `sort` `uniq` `cut` `stat` `du` `file` `jq` `echo` |
| 时间 | `date`、`TZ=Asia/Shanghai date` |
| 查库、跑脚本 | `python3`、原项目虚拟环境的 python（相对路径与绝对路径两种写法） |
| 抽帧 | `ffmpeg` `ffprobe` |
| 本地库只读 | `sqlite3 -readonly` |
| 只读查状态 | `git status/log/diff/show`、`systemctl --user status/is-active`、`journalctl --user`、`ps` |
| 文件工具 | 读、查找、写、编辑（写入受下面的 deny 限制） |

**禁止**

| 类别 | 内容 |
|---|---|
| 删改移动 | `rm` `mv` `sed -i` `tee` `chmod` `chown` |
| 提权、杀进程 | `sudo` `kill` `pkill` |
| 联网 | `curl` `wget` |
| 直连数据库 | `mysql` |
| 改版本库 | `git push/commit/add/reset/checkout/restore` |
| 控制服务 | `systemctl --user start/stop/restart/enable/disable`、`docker` |
| 写项目与成片 | 写文件与编辑工具在 `/data/projects/**`、`/data/QTS/**` 下一律禁止 |

写入因此只能落在两处：工作台（笔记、临时文件、抽帧）和机器人的记忆目录。

### 要放行一个新操作

1. 看私聊告警或控制台「统计」页，拿到被拒的原命令。
2. 判断它是不是真的需要。只读的、确实常用的才加。
3. 加进工作台 `settings.json` 的 `allow`，规则格式是 `Bash(命令前缀:*)`。
4. 不用重启任何服务，下一张卡就生效。
5. 如果是所有实例都用得上的，同时改模板，并提交。

### 两种写法一律被拒（不是清单漏配）

2026-09-23 实测，下面两种写法在受限模式下无论清单怎么配都会被拒：

| 写法 | 替代 |
|---|---|
| heredoc：`python3 - <<EOF … EOF`、`cat > 文件 <<EOF` | `python3 -c "…"`（可以多行）；或先用写文件工具存成脚本再运行；写记忆、笔记用写文件工具 |
| `for …; do …; done` 循环 | 逐条执行，或把循环写进 Python 脚本 |

管道（`ls x | head`）、`cd … && …`、`python -c "…"` 都能正常通过。

### 路径

受限模式下，机器人只能读到工作目录（工作台）和 `--add-dir` 挂进来的目录。挂哪些目录由实例配置决定：

- `project_dir`：原项目，总会挂上
- `extra_dirs`：额外要读的目录，每行一个。drama-auto 挂的是成片所在的 `/data/QTS/版权部/自动化短剧output`

**一律用绝对路径，别 `cd` 进原项目。** Bash 的工作目录在两次调用之间是保留的，`cd` 进原项目后，
后面用相对路径写的文件就会落进原项目。skill 里已经写明这条。

## 局限：拦得住顺手，拦不住刻意

必须清楚这份清单能做到什么、做不到什么：

- **`python3` 放行就等于能跑任意代码。** 机器人查库离不开 python，所以放行了；但 python 能写库、能删文件、能联网。
- **禁止写项目只拦写文件和编辑工具，拦不住 Bash 往项目里写。** 比如 `ffmpeg … -o 项目目录/x.jpg` 能写成功。
- **查库账号已换成只读的 `drama_ro`**（2026-09-24 建，只有 `drama_%` 库的 SELECT/SHOW VIEW），连接串放在
  `~/.local/state/yizhan/drama-auto/db_ro.env`。原项目 `.env` 里能写的 `drama` 账号 09-21 写过线上库，现在清单里禁读该文件，
  但 `cat` 之类仍能读到，靠的是 skill 纪律。

「不许改数据」这条规矩，现在由只读账号在数据库侧兜底（09-23 曾决定不做，09-24 改为做了）。
换口令或重建账号：SSH `<数据库主机>`，在 `mysql8` 容器内用 root 执行 `ALTER USER 'drama_ro'@'%' IDENTIFIED BY …`，再改 `db_ro.env`。

## 怎么验证一份清单

改了清单或切了模式后，用一次预演验证，不碰机器人的主会话、不往群里发消息：

```bash
cd ~/.local/state/yizhan/<实例>/workspace
YIZHAN_INST=<实例> https_proxy=http://127.0.0.1:7890 http_proxy=http://127.0.0.1:7890 \
  claude -p "这是权限预演,不要在群里发消息,不要调用 fgctl reply/send/done/defer/react。逐条执行:…,最后列出每步成功还是被拒" \
  --add-dir <项目目录> --add-dir <extra_dirs…> \
  --permission-mode dontAsk --permission-prompts none --output-format stream-json --verbose < /dev/null
```

结果最后一行（`type: result`）里的 `permission_denials` 列出了所有被拒的操作。2026-09-23 的预演：

| 操作 | 结果 |
|---|---|
| fgctl、查时间、原项目 venv 跑 python、读成片目录、ffprobe、抽帧到工作台、写工作台、写记忆 | 放行 |
| 写原项目文件、`sed -i`、`rm`、重启服务 | 被拒，无副作用 |
| 全程 | 无卡顿 |

## 切换与回退

在控制台「配置」页签改「claude 的权限参数」，或直接改实例配置：

```toml
# 受限(正式运行)
permission_args = ["--permission-mode", "dontAsk", "--permission-prompts", "none"]

# 跳过权限(只用于新实例第一天调通)
permission_args = ["--dangerously-skip-permissions"]
```

dispatcher 每轮重新读配置，下一张卡生效，不用重启服务。

切到受限模式前，工作台必须已被标为可信（`yizhan init` 会自动做），否则 claude 会忽略整份 `settings.json`，
启动时打印 `Ignoring N permissions.allow entries`，结果是什么都不许做。
